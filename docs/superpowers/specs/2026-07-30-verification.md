# DockMinimizer 검증 기록

검증일: 2026-08-03
빌드: `feat/dock-minimizer`, `/Applications/DockMinimizer.app` (self-signed `DockMinimizer Self Signed`)
환경: macOS 26.5.2 (Tahoe), arm64, 단일 디스플레이 1800×1169

검증은 대부분 자동화했다. HID 레벨(`.cghidEventTap`)로 클릭을 합성하고 대상 앱의 윈도우 최소화 상태를 AX로 직접 읽는다. 사람이 눈으로 관찰하는 방식보다 재현 가능하고, 실제로 이 방식 덕분에 Phase 0에서 잘못 내린 결론(Plan A)을 구현 단계에서 잡을 수 있었다.

도구는 스크래치패드에 있다 (`verify`, `verify2`, `clickapp`, `edge`, `race`).

## 핵심 동작

| 항목 | 결과 | 근거 |
|---|---|---|
| 최소화 → 복원 → 최소화 → 복원 토글 | PASS | 4회 연속 클릭이 매번 번갈아 동작 |
| 프론트모스트가 아닌 앱 클릭 → 평소대로 활성화 | PASS | Safari 활성화, 메모는 최소화되지 않음 |
| 최소화 직후 이웃 아이콘 클릭 | PASS | Safari 아이콘이 22.5pt 이동했음에도 올바른 앱 활성화 |
| 단위 테스트 | PASS | 24/24 |

Dock 재정렬은 실측으로 확인했다. 메모를 최소화하자 Safari 아이콘의 x좌표가 **22.5pt**(아이콘 폭 45pt의 정확히 절반) 이동했다. `DockIndex.refreshAfterWindowChange()`가 이를 흡수한다.

## 입력 변형

| 항목 | 결과 | 근거 |
|---|---|---|
| 수정자 없는 클릭 | 최소화됨 | 기준선 |
| ⌘클릭 | 개입 안 함 | `ClickRouter`의 수정자 가드 |
| 옵션클릭 | 개입 안 함 | 동일 |
| 우클릭 | 개입 불가 | 이벤트 마스크가 leftMouseDown/Up 뿐이라 구조적으로 도달하지 않는다 |
| 프론트모스트 앱 아이콘 드래그 | **동작하지 않음 (알려진 제약)** | 아래 참조 |

**드래그 제약:** 프론트모스트 앱 아이콘의 mouseDown을 삼키므로 Dock이 드래그를 시작하지 못한다. 통과시키면 Dock이 우리 최소화를 되돌리므로 양립할 수 없다. 다른 아이콘의 드래그는 영향받지 않는다.

## 남은 항목 — 사람이 확인해야 함

자동화하지 못했거나 이 환경에서 재현할 수 없는 것들이다.

- [ ] **멀티 디스플레이** — 단일 디스플레이 환경이라 측정 불가. Dock이 있는 화면과 없는 화면 양쪽에서 확인 필요
- [ ] **"윈도우를 앱 아이콘으로 최소화" 켬** — 이 설정에서는 Dock에 아이콘이 추가되지 않으므로 재정렬 문제가 사라진다. 끔(기본값) 상태만 검증했다
- [ ] **여러 스페이스에 걸친 윈도우**
- [ ] **윈도우 0개인 메뉴바 전용 앱** — `.ignore`로 판정되어야 한다
- [ ] **장시간 실행 (수 시간)** — 이벤트 탭이 죽지 않는지. `log show ... | grep -E '느립니다|비활성화'`가 비어 있어야 한다
- [ ] **권한 회수/재부여의 즉시 반영** — 실측에서 권한 **부여**는 실행 중인 프로세스에 반영되지 않았고 재시작이 필요했다. 회수 방향은 측정하지 못했다. 앱은 두 경우 모두를 처리한다: 권한은 있는데 탭이 없으면 메뉴바가 `권한 부여됨 — 재실행해야 적용됩니다`를 표시하고 `재실행` 항목을 보여 준다
- [ ] **설정 창 UI** — 활성화 토글, 제외 앱 추가·제거(`NSOpenPanel`), 권한 상태 표시
- [ ] **로그인 시 시작** — `SMAppService.mainApp` 등록/해제
- [ ] **기능을 끈 뒤 전부 최소화된 앱의 복구 경로** — Dock의 최소화 윈도우 항목으로 복구 가능한지

## 검증 중 발견해 고친 결함

1. **Plan A(리슨 전용 탭)가 틀렸다.** Phase 0에서 "Dock은 아무 것도 하지 않는다"고 결론냈으나, 그것은 되돌릴 대상이 없을 때의 관찰이었다. 우리가 최소화하면 Dock이 같은 클릭을 처리하며 100ms 안에 원상복구한다. `AXUIElementSetAttributeValue`가 `.success`를 반환하고 로그도 정상이라 증상은 "아무 일도 일어나지 않음"으로만 보였다. 액티브 탭 + 클릭 삼킴으로 수정.

2. **삼킴 플래그에 유효 기간이 없었다.** 짝이 되는 mouseUp이 끝내 오지 않으면 플래그가 남아 한참 뒤의 무관한 클릭을 삼킨다. 1초 유효 기간을 부여.

3. **측정 도구 자체의 함정.** `CGEvent.post(tap: .cgSessionEventTap)`로 보낸 합성 클릭은 Dock에 전달되지 않는다. `.cghidEventTap`으로 보내야 한다. 이것을 모르고 측정하면 모든 결과가 "아무 일도 일어나지 않음"으로 나와 잘못된 결론에 이른다.
